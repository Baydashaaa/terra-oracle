# Markets - состояние на 26 сентября 2026

Раздел прогнозов Terra Oracle Classic. Документ для продолжения работы в новом
диалоге: что построено, где лежит, что решено, что проверено и что осталось.

---

## 1. Как устроено

Три части, каждая в своём репозитории:

| Часть | Репозиторий | Что делает |
|---|---|---|
| **oracle-prophecy** | Baydashaaa/oracle-prophecy | Контракт рынков: паримьючел-пул в LUNC, создание, предсказания, объявление исхода, оспаривание, расчёт, выплаты |
| **oracle-court** | Baydashaaa/oracle-court | Контракт суда - арбитр рынков. Равный голос, совет разработчиков, кворум, заморозка правил дела |
| **сайт и керпер** | Baydashaaa/terra-oracle | Раздел Markets на сайте и скрипт керпера в GitHub Actions |

### Жизнь рынка

```
create (кто угодно, залог)
  -> open: предсказания на YES / NO
  -> bets_close_at: приём закрыт
  -> resolve_after: керпер читает метрику на высоте из спеки и объявляет исход (propose)
  -> proposed: окно оспаривания (challenge_secs)
       никто не оспорил -> керпер делает settle -> выплаты
       оспорили (залог)  -> disputed -> суд голосует -> close -> рынок рассчитан
                                     -> суд не успел за arbiter_secs -> expire -> void, всем возврат
  -> нет объявления за resolve_grace_secs -> expire -> void, всем возврат
```

Экономика: комиссия только с проигравшего банка - 5% протокол (пополам недельный пул и казна),
3% создателю, 2% в фонд доплат, 90% победителям. Если оспоривший прав - протокольная доля
этого рынка уходит ему вместе с возвратом залога.

## 3. Контракты - что в них важно

### oracle-prophecy 0.2.2

- **Сообщение предсказания - `predict`**, старое `bet` принимается как синоним. В событии
  транзакции по-прежнему `action: bet` - на нём держатся керпер и график, не менять
- `challenge` - кто угодно, кроме резолвера и арбитра, с точным залогом `challenge_bond`
- `rule` - только арбитр, в течение `arbiter_secs`, решение окончательное
- `expire` - кто угодно: после grace без объявления или после окна арбитра без решения
- В рынке хранятся `void_reason`, `bad_spec`, `challenger`, `challenge_reading`, `ruling`, в спеке - `unit`
- Все новые поля на `#[serde(default)]`, иначе старые записи не читаются. Тест
  `storage_written_by_the_old_code_still_reads` это проверяет
- **Доплата только продвигаемым рынкам** (`boost_eligible`, с 0.2.2). Иначе создатель
  ставит в одиночку на очевидную сторону и забирает доплату: при пустой второй стороне
  проигравший банк - это одна доплата. Продвижение дороже доплаты, накрутка убыточна.
  Тесты `only_promoted_markets_get_the_boost`, `farming_the_boost_stays_unprofitable`
- Запрос `boost` отдаёт счётчик недели без её начала и не обнуляет его сам: после смены
  недели показывает старое число, хотя создание бонус выдаст. Исправить в 0.2.3
- 42 теста: `cargo test --tests` (17 + 17 + 8)

### oracle-court 0.1.0

- Первый голос сам открывает дело. Правила (совет, кворум, источник права голоса)
  копируются в дело при открытии и дальше не меняются
- Не голосуют: резолвер, оспоривший, любой со ставкой в рынке - проверяется у рынка
- Ничья наверху или меньше кворума - VOID
- `vp_source` - будущий Oracle Vault, интерфейс `{"eligible":{"address","at"}}`
- `voting_secs` обязан быть меньше `arbiter_secs` рынка
- Тесты в отдельном крейте `integration/`, гоняются против настоящего oracle-prophecy:
  `cd integration && cargo test` (15), нужен `../../oracle-prophecy`
- Порядок развёртывания: рынок с временным арбитром -> суд с адресом рынка ->
  `update_config { arbiter: <суд> }` на рынке

Доступ:

  Сервер запрещает кеш (правки видны после F5) и отдаёт `index.html` на пути сайта (`/markets`)

Лимиты газа по замерам: предсказание 600k, выплата 800k, создание 700k, оспаривание 600k,
голос 1.1M, закрытие 1.8M, аннулирование 1.2M.

Сайт отправляет `predict` на rebel-2 и `bet` на mainnet, где пока старый 0.1.0.
Сообщение задаёт поле `predictMsg` в `PROPHECY_NET` в `markets.js`.

График прогноза рисуется от двух предсказаний на рынке; при одном его нет.

Прошедшие день, месяц и час в дате разрешения в форме недоступны. Выпадающие
списки прокручиваются внутри себя и открываются на выбранном значении.

Кнопка **How it works** (вместо Browse markets) открывает окно из трёх вкладок: Predict
(пример пула, полоса комиссий), Outcome (шаги исхода), Create (залог, заработок,
продвижение). Все суммы, сроки и доли читаются из конфига контракта - после смены
параметров или сети окно правок не требует. Постоянный только пример 6,000 / 4,000 / 1,000.

Зазор перед разрешением в форме - не меньше max(`bet_cutoff_secs`, 3% оставшегося срока).
Короткие варианты недоступны, есть вариант 7 дней.

Шаг 5 формы - **Promotion**: переключатель с ценой из конфига и статусом бонуса из
запроса `boost` (будет ли, сколько осталось на неделе), читается при каждом открытии формы.

## 5. Керпер

- `scripts/markets-keeper.js` + `.github/workflows/markets-keeper.yml`, раз в 10 минут
- Подпись как у `oracle-score-attest.js`: HTTP и protobuf руками, без cosmjs
- Объявляет исход только ончейн-метрик и только если его ключ - резолвер рынка.
  Читает метрику на высоте из спеки, сравнивает в BigInt (саплай 6.45×10^18 не помещается в Number)
- Делает settle, закрывает дела суда, аннулирует зависшее. Каждое действие сначала симулируется
- `DRY_RUN=1` - только план
- **Проверка дрейфа** перед `propose`: время блока на высоте из спеки. Позже закрытия
  приёма - объявляет. Раньше и есть предсказание на этой высоте или позже - `void`
  с причиной (`bad_spec: false`, всем возврат). Раньше, но предсказаний после высоты нет -
  объявляет. Блок или поиск не ответили - ждёт следующего прохода
- Workflow не запускается, пока в переменных репозитория нет `PROPHECY_CONTRACT`. На rebel-2
  он не настроен и не будет: там керпер только руками. Письма GitHub «job was skipped» - это оно
- Переменные: `PROPHECY_CONTRACT`, `COURT_CONTRACT`, `EXPECTED_KEEPER`, `KEEPER_CHAIN_ID`,
  `KEEPER_LCD_URLS`, `KEEPER_DRY_RUN`; секрет `KEEPER_MNEMONIC`
- Локальный прогон на rebel-2: `export PROPHECY_CONTRACT=… COURT_CONTRACT=… CHAIN_ID=rebel-2
  LCD_URLS=https://lcd.luncblaze.com`, затем `read -rs KEEPER_MNEMONIC && export KEEPER_MNEMONIC`,
  затем `node scripts/markets-keeper.js`

## 6. Решения

- Предсказания на LUNC, паримьючел, без ордербука
- Создавать может кто угодно. Сейчас только ончейн-метрики; свободный критерий - позже
- Категории в форме: Economy, Governance, Validators, Network. Protocol скрыт, пока нет метрик
- Markets - отдельная страница, не вкладка борда
- Залог создания **200,000 LUNC**, залог оспаривания **200,000 LUNC**
- Grace **7 дней**, окно суда на решение **72 часа**
- Арбитр - суд (DAO): равный голос, совет из трёх разработчиков сейчас, пользователи
  позже через Oracle Vault (позиция ликвидности даёт право голоса и доход)
- Везде в интерфейсе «prediction», не «bet»
- Плата за продвижение **250,000 LUNC**, в казну
- Доплата **50,000 LUNC** из фонда, только продвигаемым рынкам, **до 3 в неделю**. Фонд на
  запуске пополняется из казны через `fund_boost` (предложено ~1,000,000 LUNC)
- Затравка пула из залога создателя (вариант Б) отклонена: делает создание дороже и страшнее
- Защита от дрейфа блоков - и в керпере, и в форме
- REP создателям за рассчитанный рынок с участниками на обеих сторонах - решено, не сделано
- Промо в CW20 - в 0.3: белый список токенов, цены обновляет керпер по API OrbitWire,
  оплата через `Receive`. Не к запуску
- Предложено, явно не подтверждено: минимум 1,000, максимум 1,000,000 на кошелёк на рынок,
  окно оспаривания 24 ч, голосование суда 48 ч
- Админ всех контрактов - `pool-admin-2`. Старый `terra1744ae9…cxtc` засвечен и нигде больше не админ

## 8. Грабли

- `let globalWalletAddress` в wallet.js не становится `window.globalWalletAddress` - адрес

## 10. Как работаем

- Правки приходят скриптами `.py`, которые кладутся в `Downloads` и запускаются из корня
  репозитория. Каждая правка ищет точный фрагмент; не нашла - скрипт останавливается и ничего не пишет
- Команды - bash в WSL Ubuntu, репозитории в `~`
- В текстах и коде - обычный дефис, без длинного тире
